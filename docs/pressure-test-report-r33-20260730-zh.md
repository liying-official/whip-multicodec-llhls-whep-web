# R33 直播与 v25 监控双轮压力测试报告（中文）

测试日期：2026-07-30（UTC+8）  
测试对象：R33 直播服务与 v25 旁路监控  
测试机：Debian 13，16 vCPU，7,943.41 MiB RAM，1 GiB Swap  
结论：两轮有效正式测试均通过，未发现新的直播或监控功能缺陷。

## 1. 测试目标

| 轮次 | 生成器 | 用户数 | 视频码率 | 持续时间 | 理论输出 |
|---|---:|---:|---:|---:|---:|
| 第一轮 | 2 × 100 | 200 | 50 Mbps/用户 | 600 秒 | 10 Gbps |
| 第二轮 | 2 × 5,000 | 10,000 | 1 Mbps/用户 | 600 秒 | 10 Gbps |

两个负载生成器均运行在测试机上，通过回环地址访问 R33 HLS 入口。每个虚拟用户独立建立认证会话，以固定 2 秒周期读取播放列表和最新媒体分片。测试机资源统计包含 R33、监控、FFmpeg 测试推流以及两个生成器自身的消耗。

测试流均为 H.264/AVC + AAC。第一轮监控实测输入码率约 50.008 Mbps；第二轮视频编码参数严格设为 CBR 1 Mbps，监控统计的流平均码率约 1.007 Mbps。

## 2. 总体结论

- 两轮正式测试均完整运行超过 600 秒。
- 两轮播放列表和媒体分片请求错误均为 0，成功率均为 100%。
- 第一轮实际平均输出 9.997 Gbps；第二轮实际平均输出 10.048 Gbps。
- R33 和 v25 监控在两轮中始终保持 `active`，服务重启计数均未增加。
- 监控 API 所有正式采样均返回 HTTP 200，SQLite 健康检查全程正常。
- 正式时间窗口内没有 systemd warning、OOM、TCP 内存耗尽、段错误或 hung-task 内核事件。
- 两轮均未使用 Swap。
- 停流后 HLS/WebRTC 会话立即降为 0；60 秒续播宽限结束后直播正确转为离线，SQLite 正确写入结束状态。

两轮正式测试的测试机总体峰值：

| 指标 | 两轮总体峰值 |
|---|---:|
| 最大系统 CPU | **74.76%** |
| 最大系统 RAM 已用 | **4,707.07 MiB（4.60 GiB）** |
| 最大 Swap 已用 | **0 MiB** |

最大 CPU 出现在第二轮；最大 RAM 出现在第一轮的高码率分片场景。

## 6. 最终判断

在两种均约 10 Gbps、但会话规模和单流码率差异显著的模型下：

1. R33 直播输出没有请求错误、崩溃或服务重启。
2. v25 监控能够在 200 和 10,000 用户下持续正确统计在线人数、会话和带宽。
3. 10,000 用户场景的监控 API p95 延迟升至约 341 ms，但仍保持 100% HTTP 200，不属于功能故障。
4. 第一轮高码率场景以内存压力为主；第二轮高会话场景以 CPU 压力为主。
5. 未发现需要立即修改直播包或监控包的新 bug。
