防火墙边界：公网观看、内网推流 / Firewall: public viewing, LAN publishing
========================================================================
项目版本 / Project version: v1.35

中文
----

程序默认边界
- WHIP TCP/8889 与 RTMP TCP/1935 只绑定 WHIP_IP，不绑定所有网卡。
- WHIP_IP 必须是本机已启用网卡的 RFC1918 私网 IPv4。留空时优先选默认路由
  对应网卡；多网卡时可显式选择该地址。
- obs 发布账号只允许 live 路径，必须同时满足随机密码和“所选网卡真实局域网段
  + WHIP_IP/32”来源检查。INGEST_ALLOW_CIDRS 的手工值会被忽略。
- 网关 TCP/8080、HLS TCP/8888、metrics TCP/9998 都只绑定 127.0.0.1。
- API、RTSP、SRT、MoQ、pprof、playback 和录制关闭；Caddy 管理 API 关闭。
- 公网仅代理观看页面、HLS 和受限的 /rtc/live/whep 会话接口；/live/whip、
  /live/whep、MediaMTX 内置播放页和其他未允许路径不对外开放。

来源检查依据服务器实际看到的源 IP。NAT/代理若把外部来源改写为获准局域网地址，
会掩盖原始来源；不能据此保证误转发的公网发布始终被拒绝。因此不要把 8889/1935
映射到公网，也不要用代理替外部发布者改写来源。

主机防火墙应保留第二层限制。把规则合并进现有规则集并先保留 SSH 管理来源；
不要在远程 SSH 会话中直接 flush 现有 nftables 表。

端口与 NAT
服务器本机：
  TCP/443   HTTPS：HTTP/1.1 + HTTP/2，仅 TLS 1.3
  UDP/443   HTTP/3 / QUIC，仅 TLS 1.3
  UDP/8189  WebRTC DTLS-SRTP 加密媒体，首选
  TCP/8189  WebRTC 加密媒体回退
  TCP/8889  仅所选可信局域网：WHIP 信令
  TCP/1935  仅所选可信局域网：RTMP

start.sh 的 PUBLIC_HTTPS_PORT 内置默认是 443，实际使用 config.env 的设置。
若公网端口不是 443，分别配置同协议映射：
  TCP/PUBLIC_HTTPS_PORT -> 服务器 TCP/443
  UDP/PUBLIC_HTTPS_PORT -> 服务器 UDP/443
例如公网 8443 映射到服务器 443，主机 input 防火墙仍应放行本机 443。
两种协议的公网端口须相同，以匹配观众 URL 与 HTTP/3 Alt-Svc。仅 TCP 可播放
HTTP/1.1/2，但无法使用 HTTP/3。

公网 WHEP 还需把 UDP/8189、TCP/8189 按原端口转发至服务器。8189 是经过 ICE/
DTLS 协商的媒体端口，不是发布信令接口；WHIP 推流也使用该媒体端口。仅向公网
提供 LL-HLS 时可以不向公网开放 8189，局域网推流客户端所需媒体访问仍应保留。
当前公网 WHEP ICE 白名单仅公告 PUBLIC_HOST 的合格 IPv4，不能通过只开放
IPv6/8189 来提供公网 IPv6 WHEP 媒体路径。

发布来源
配置自动选择示例（不是已分发 config.env 的内容保证）：
  WHIP_IP=
  INGEST_ALLOW_CIDRS=

启动按所选接口的 <LAN_IP>/<PREFIX_LENGTH> 生成：
  <LAN_CIDR>
  <LAN_IP>/32

仅在防火墙中放行其他 VPN 地址池不会扩大程序发布权限；来源仍必须符合上述
接口范围和密码校验。不要将任意 VPN 网段或 0.0.0.0/0 描述为默认可发布来源。

nftables 片段
以下仅为现有 inet input 链中的顺序示例，不含 SSH、loopback、established/
related 等基础规则，不是可直接覆盖整套防火墙的脚本：
  tcp dport 443 accept
  udp dport 443 accept

  # 公网 WHEP 媒体；公网仅提供 HLS 时可省略。
  udp dport 8189 accept
  tcp dport 8189 accept

  ip saddr <LAN_CIDR> tcp dport { 8889, 1935 } accept
  tcp dport { 8889, 1935 } drop

先写内网 accept，再写发布端口 drop。按自己的接口和现有基础规则收紧入口；
云安全组、路由器转发和主机防火墙都应保持相同边界。不要向公网开放 TCP/80、
8080、8888、9998、8889 或 1935。

IPv6 与验证
PUBLIC_DOMAIN 的 HTTPS 可按需使用 IPv6，但观众访问的端口仍须匹配
PUBLIC_HTTPS_PORT。WHIP/RTMP 仅绑定所选 IPv4；公网 WHEP 的 ICE 媒体路径
仍遵循上述 IPv4 白名单。

启动后运行：
  sudo ./diagnose.sh
  ss -lntup

诊断应报告：
  SECURITY: PASS - 发布控制端口未使用 wildcard 监听

核对 8889/1935 的 Local Address 为 WHIP_IP，而非 0.0.0.0、* 或 [::]；
8080/8888/9998 为 127.0.0.1。MediaMTX 的 UDP/TCP 8189 使用通配媒体监听，
不要误把媒体监听当成发布信令越界。

English
-------

Application boundaries
- WHIP TCP/8889 and RTMP TCP/1935 bind only to WHIP_IP, not every interface.
- WHIP_IP must be an RFC1918 IPv4 address on an active local interface. When empty,
  the interface associated with the default route is preferred. Set it explicitly
  to select an interface on a multihomed server.
- The obs account can publish only to live. Both the random password and the
  detected interface subnet plus WHIP_IP/32 source check must pass. Manual
  INGEST_ALLOW_CIDRS values are ignored.
- Gateway TCP/8080, HLS TCP/8888 and metrics TCP/9998 bind only to 127.0.0.1.
- API, RTSP, SRT, MoQ, pprof, playback and recording are disabled; so is Caddy's
  administration API.
- The public site proxies only the player, HLS and restricted /rtc/live/whep
  session operations. /live/whip, /live/whep, MediaMTX's built-in player and other
  unapproved paths are not exposed.

Source checks use the IP address actually seen by the server. NAT/proxy source
rewriting to an approved LAN address can hide an external origin; the application
cannot guarantee rejection of every accidentally forwarded public connection.
Do not forward 8889/1935 publicly or proxy external publishers behind an approved
LAN source address.

Keep host firewall rules as a second layer. Merge rules into the existing ruleset
and preserve SSH management access first. Do not flush existing nftables tables
from a remote SSH session.

Ports and NAT
Local server listeners:
  TCP/443   HTTPS: HTTP/1.1 + HTTP/2, TLS 1.3 only
  UDP/443   HTTP/3 / QUIC, TLS 1.3 only
  UDP/8189  WebRTC DTLS-SRTP encrypted media, preferred
  TCP/8189  WebRTC encrypted media fallback
  TCP/8889  WHIP signalling, selected trusted LAN only
  TCP/1935  RTMP, selected trusted LAN only

The built-in PUBLIC_HTTPS_PORT default in start.sh is 443; config.env controls the
effective value. For a nonstandard public port, map each protocol separately:
  TCP/PUBLIC_HTTPS_PORT -> server TCP/443
  UDP/PUBLIC_HTTPS_PORT -> server UDP/443
For example, public port 8443 maps to local port 443, so the host input firewall
still allows local port 443. Public TCP and UDP ports must match the viewer URL
and HTTP/3 Alt-Svc. A TCP-only mapping supports HTTP/1.1/2 but not HTTP/3.

Public WHEP additionally needs UDP/8189 and TCP/8189 forwarded without changing
the port number. Port 8189 carries ICE/DTLS-negotiated media, not publishing
signalling. WHIP ingest uses this media port too. For public HLS-only viewing,
8189 may remain closed to the Internet while retaining the media access needed by
LAN publishing clients. Public WHEP ICE advertises only approved PUBLIC_HOST IPv4 addresses;
opening IPv6/8189 alone does not provide a public IPv6 WHEP media path.

Publishing sources
Example for automatic selection (not a guarantee of the distributed config.env):
  WHIP_IP=
  INGEST_ALLOW_CIDRS=

Startup derives the source allowlist from the chosen <LAN_IP>/<PREFIX_LENGTH>:
  <LAN_CIDR>
  <LAN_IP>/32

Allowing another VPN address pool in the firewall does not expand application
publishing permissions. Sources must still satisfy the detected interface range
and password check. An arbitrary VPN subnet or 0.0.0.0/0 is not an allowed
publishing source by default.

nftables fragment
This is an ordering example for an existing inet input chain. It omits SSH,
loopback, established/related and other base rules; it is not a replacement
firewall script:
  tcp dport 443 accept
  udp dport 443 accept

  # Public WHEP media; omit for public HLS-only viewing.
  udp dport 8189 accept
  tcp dport 8189 accept

  ip saddr <LAN_CIDR> tcp dport { 8889, 1935 } accept
  tcp dport { 8889, 1935 } drop

Place the LAN accept rule before the publishing-port drop. Restrict interfaces
as appropriate to your existing rules. Keep cloud security groups, router
forwarding and the host firewall consistent. Do not expose TCP/80, 8080, 8888,
9998, 8889 or 1935 to the Internet.

IPv6 and verification
HTTPS for PUBLIC_DOMAIN may use IPv6, but its externally reachable port must
still match PUBLIC_HTTPS_PORT. WHIP/RTMP bind only to the selected IPv4 address;
public WHEP media continues to use the IPv4 ICE allowlist described above.

After startup, run:
  sudo ./diagnose.sh
  ss -lntup

Expected diagnostic:
  SECURITY: PASS - 发布控制端口未使用 wildcard 监听

Verify that the local addresses for 8889/1935 are WHIP_IP, not 0.0.0.0, * or [::],
and that 8080/8888/9998 bind to 127.0.0.1. MediaMTX uses wildcard UDP/TCP media
listeners on 8189; these are not wildcard publishing signalling listeners.
