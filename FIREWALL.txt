Debian 13 防火墙边界：公网观看、内网推流
==========================================

程序内已经实施
--------------
- TCP/8889（WHIP）只绑定 WHIP_IP，不绑定 0.0.0.0 或 IPv6 wildcard。
- TCP/1935（RTMP）只绑定 WHIP_IP。
- obs 发布账号同时校验随机密码和启动时自动生成的“接口局域网段 + 本机 /32”。
- 127.0.0.1:8080 与 127.0.0.1:8888 只供本机 Caddy/MediaMTX 使用。

主机防火墙仍应做第二层限制。不要在远程 SSH 会话中直接 flush 现有 nftables 表；
应把规则合并进当前规则集，并先保留 SSH 管理来源。

公网观看必须允许
----------------
  TCP 443  HTTP/1.1 + HTTP/2 / TLS 1.3
  UDP 443  HTTP/3 / QUIC / TLS 1.3

公网 WHEP/WebRTC 播放还需要：
  UDP 8189  DTLS-SRTP 媒体（首选）
  TCP 8189  DTLS-SRTP 媒体回退

8189 不是 WHIP/RTMP 发布信令端口。公网网页使用 WebRTC/AV1 回退时需要它；如果
网页永远只使用 LL-HLS，可以不向公网开放 8189。

仅允许启动识别出的同网段局域网来源
--------------------------------
  TCP 8889  OBS WHIP 信令
  TCP 1935  OBS RTMP 兼容推流

示例来源网段：
  192.168.50.0/24

程序会在启动时识别例如 192.168.50.10/24 的本机网卡，并自动生成：
  192.168.50.0/24
  192.168.50.10/32

config.env 通常保持：
  WHIP_IP=
  INGEST_ALLOW_CIDRS=

多网卡服务器可用 WHIP_IP 选择某个本机私网地址；INGEST_ALLOW_CIDRS 手工值
会被忽略，不能增加其他网段。

nftables 规则片段（合并进现有 input 链）
---------------------------------------
以下只是规则顺序示例，不包含 SSH、established/related、loopback 等基础规则：

  tcp dport 443 accept
  udp dport 443 accept

  # 公网 WHEP 需要；只用 LL-HLS 时删除这两条。
  udp dport 8189 accept
  tcp dport 8189 accept

  ip saddr 192.168.50.0/24 tcp dport { 8889, 1935 } accept
  tcp dport { 8889, 1935 } drop

先写内网 accept，再写发布端口 drop。若使用 VPN，把 VPN 地址池加入 accept；不要用
0.0.0.0/0。云安全组、路由器端口转发和宿主机防火墙三处都应保持相同边界。

不应向公网开放
--------------
  TCP 80
  TCP 8080
  TCP 8888
  TCP 8889
  TCP 1935

IPv6
----
Caddy 的公网 443 可以按需提供 IPv6。WHIP/RTMP 只绑定指定 IPv4，不提供公网 IPv6
发布入口。若开放公网 WHEP 的 IPv6 8189，仍只承载经 WHEP 会话协商的加密媒体。

验证
----
启动后运行：

  sudo ./diagnose.sh

应看到：
  SECURITY: PASS - 发布控制端口未使用 wildcard 监听

并用 ss 确认 TCP/8889、TCP/1935 的 Local Address 是 WHIP_IP，而不是
0.0.0.0、* 或 [::]。
